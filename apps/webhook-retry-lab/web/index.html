WHAT THE MODEL TEACHES

Deduplication and recovery
are different jobs.

01

Don’t use an execution ID

A new workflow execution gets a new ID. Deduplication needs the same stable key for the same logical event.

02

A flag can hide lost work

If you mark an event as seen and crash before the action, a retry may skip work that never happened.

03

The destination matters

After an external action succeeds, a crash can make its result uncertain. A state ledger alone cannot prevent the action happening twice.

Model assumptions & sources

All deliveries are sequential copies of one fixed event. The first delivery may crash at the selected boundary. A recoverable lease is assumed to have expired before the next retry. Destination idempotency, when enabled, is assumed to persist for the entire scenario. The model does not test concurrent claims, real databases, network timeouts, retry scheduling, key expiry or production configuration. One action in this model does not prove exactly-once delivery in a real system.

Sources: Stripe webhook delivery documentation, Stripe idempotent requests, n8n HTTP Request.
